TECH TIP #001 · GIT

Cómo recuperar un commit perdido con git reflog

Un reset o un rebase puede hacer que un commit deje de aparecer en el historial normal. Antes de darlo por perdido, consulta el registro local de movimientos de Git.

26 de julio de 2026 5 min de lectura Revisado técnicamente
La idea que debes recordar

git reflog registra localmente dónde han apuntado HEAD y otras referencias. Si el objeto del commit sigue disponible, puedes volver a hacerlo alcanzable creando una rama.

01 · El problema

El commit ya no aparece en git log

Imagina que ejecutas un git reset --hard HEAD~2 y después descubres que necesitabas uno de los commits anteriores. La rama ha retrocedido y ese commit puede haber desaparecido de git log, pero eso no significa necesariamente que Git haya borrado el objeto de inmediato.

02 · Localízalo

Consulta los movimientos recientes de HEAD

Ejecuta el comando dentro del repositorio en el que hiciste el cambio:

terminal
$ git reflog
a1b2c3d HEAD@{0}: reset: moving to HEAD~2
9f8e7d6 HEAD@{1}: commit: añade autenticación
4c3b2a1 HEAD@{2}: commit: estructura inicial

Cada línea incluye un identificador de commit, una referencia temporal como HEAD@{1} y una explicación del movimiento. Busca la entrada anterior a la operación que causó el problema.

03 · Recupéralo

Crea una rama nueva en el commit correcto

Cuando hayas comprobado el hash, la opción más segura es crear una rama de recuperación. Así no mueves tu rama actual y el commit vuelve a quedar referenciado.

terminal
$ git switch -c recovery/auth 9f8e7d6
  1. Inspecciona. Usa git show 9f8e7d6 para confirmar que es el commit que buscas.
  2. Protege. Crea una rama con git switch -c o git branch.
  3. Decide. Desde ahí puedes conservar la rama, hacer cherry-pick o integrar el cambio como corresponda.

04 · El matiz importante

El reflog es local y no dura para siempre

El historial normal de Git se comparte mediante remotos; el reflog no. Describe los movimientos ocurridos en ese clon concreto. Además, las entradas antiguas pueden caducar y los objetos no alcanzables pueden eliminarse durante el mantenimiento del repositorio.

Actúa cuanto antes. Si detectas una pérdida, evita operaciones de limpieza y crea una rama en el commit correcto en cuanto lo encuentres.

05 · Resumen

Tres comandos, una recuperación segura

git reflogEncuentra el estado anterior.
git show <hash>Comprueba el commit.
git switch -c <rama> <hash>Vuelve a hacerlo alcanzable.
